# BSPRJ

Основной проект прошивки шумового мониторинга на `ESP32`, созданный из успешного тестового проекта `BS Test WPM`, с:

- микрофоном `INMP441` как текущим цифровым `I2S` источником
- OLED `SSD1306 128x64` по I2C

## Статус

- Тип: основной firmware-проект
- Текущая версия: `0.1.55-EXP`
- Текущая сборка: `109`
- GitHub: `https://github.com/allinnprj/BSPRJ`
- Модель веток: `main` = релиз/стабильная версия, `devlop` = тестовая разработка
- Активный микрофонный этап: `INMP441` по `I2S`

## Основная цель

Главная цель проекта - понять, **когда** шум высокий, а когда низкий, и сделать это понятным как по цифрам, так и по человекочитаемым уровням.

Проект должен отвечать на два главных вопроса:

- в какое время суток обычно шумно, а в какое тихо
- какой тип уровня шума характерен для этого времени суток

Для этого проект опирается на две оси анализа:

- `DAY / EVENING / NIGHT` - статистика по частям суток
- `SILENT / NORMAL / LOUD / PEAK` - качественная интерпретация уровня шума

Долгосрочное направление проекта:

- вырасти из локального single-device прототипа в систему шумового мониторинга, которую можно масштабировать дальше
- позже добавить более честный аудиотракт, геопривязку, сравнение точек наблюдения, поиск аномалий и карту шумовой среды
- при этом не терять текущий главный принцип: сначала надёжно понять **когда** и **насколько** шумно, а уже потом усложнять платформу

## Словарь состояний

В проекте важно не смешивать две разные группы состояний:

- `CLIP / LOW / OK`
  - это техническое состояние входного сигнала
  - `CLIP` = цифровой сигнал `INMP441` упирается в рабочий предел и выглядит как насыщение
  - `LOW` = сигнал слишком слабый или размах слишком мал
  - `OK` = вход выглядит нормальным
  - `LOW_HOLD` = слабый сигнал держится уже достаточно долго, чтобы считать это устойчивой проблемой
  - `CLIP_HOLD` = clipping держится уже достаточно долго, чтобы считать это устойчивой проблемой

- `SILENT / NORMAL / LOUD / PEAK`
  - это пользовательский уровень шума
  - это не качество входа, а интерпретация наблюдаемого уровня

Короткое правило:

- `CLIP / LOW / OK` = signal quality state
- `SILENT / NORMAL / LOUD / PEAK` = user-facing noise level

Итоговая прикладная цель:

- определить средний уровень шума днём, вечером и ночью
- понять, какой уровень чаще всего характерен для каждого периода
- например: ночью чаще `SILENT`, вечером чаще `NORMAL`, днём чаще `LOUD`

Все дальнейшие решения по коду, MQTT, Datacake, дисплею и железу должны поддерживать именно эту цель, а не просто собирать телеметрию ради телеметрии.

## Техническая цель текущего этапа

Продолжать проект от уже проверенной базы `ESP32`:

- вывод текста на OLED
- живой уровень микрофона
- краткосрочная и долгосрочная статистика шума
- Wi-Fi, время, локальный журнал, OTA, Telegram, Google Sheets и диагностика здоровья уже входят в текущую проверенную базу

На этом этапе проект уже полностью сфокусирован на `INMP441`, поэтому базовый цикл читает цифровой `I2S` сигнал напрямую и дальше оптимизируется уже именно вокруг этого микрофона.

## Roadmap

### Сейчас

- довести текущий `ESP32 + INMP441` до спокойного, предсказуемого состояния
- закрепить аналитику `DAY / EVENING / NIGHT`
- закрепить человекочитаемые уровни `SILENT / NORMAL / LOUD / PEAK`
- держать `MQTT` быстрым и удобным для `MqttDesk`
- держать `Datacake` как лёгкий показательный cloud-вариант

### Следующий этап

- убрать остаточное подвисание старта
- включить мягкое энергосбережение уровня 2
- при необходимости добавить контекст среды через `SHT31` и `BH1750`
- улучшить Google Sheets как дополнительный журнал наблюдений

### Фокус текущего железа

- стабилизировать новый цифровой аудиотракт `INMP441` перед следующими аппаратными шагами
- использовать `FNIRSI FDM01` как внешний референс для проверки и будущей калибровки
- подключить `Neo-8M` для точного времени и, если нужно, геопривязки
- подключить `SIM800L` как дополнительный канал связи, а не как основной поток телеметрии

### Умная версия

- определять типичный шум для дня, вечера и ночи
- выявлять отклонения от обычного профиля
- отмечать, когда шум нетипично высокий для текущего времени суток
- позже улучшать фильтрацию грязного сигнала и ветрового шума
- нейросеть на `ESP32` рассматривать только в самом конце, если она действительно нужна

## Текущее поведение

Прошивка сейчас показывает на OLED относительные уровни звука:

- `Now` - текущий уровень
- `H` - среднее за последний час
- `M` - среднее за всё время работы с момента запуска
- сообщение о прогреве, пока часовое окно ещё не заполнено

Это относительные уровни, а не откалиброванные `dB`.
Текущая прошивка уже включает Wi-Fi, синхронизацию времени, локальный журнал, OTA, Telegram-оповещения, Google Sheets диагностику и контроль SHT31.
